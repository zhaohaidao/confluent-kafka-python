# Tools


## download-s3.py

To download CI build artifacts from S3, set up your AWS credentials
and run `tools/download-s3.py <tag|sha1>`, the artifacts will be downloaded
into `dl-<tag|sha1>`.

To upload binary packages to PyPi (test.pypi.org in this example to be safe), do:

    $ twine upload -r test dl-<tag|sha1>/*


## manylinux build

To build the manylinux Python packages follow these steps:

**NOTE**: Docker is required.

Install cibuildwheel:

    $ pip install -r tools/requirements-manylinux.txt

Build using cibuildwheel:

    $ tools/cibuildwheel-build.sh wheelhouse

To build against a local librdkafka source tree, set `RDKAFKA_SOURCE_DIR`:

    $ RDKAFKA_SOURCE_DIR=/path/to/librdkafka tools/cibuildwheel-build.sh wheelhouse

The build defaults to Python 3.11 only (override with `CIBW_BUILD` if needed).

To skip Python platform configurations, use glob matching in CIBW_SKIP env.
This example only builds for Python 2.7 x64:

    $ CIBW_SKIP="cp3* cp*i686*" tools/cibuildwheel-build.sh wheelhouse

Packages will now be available in wheelhouse/


## run_auth_csv_tests.py

Run authentication test cases from a CSV shaped like `auth_tests_verification.example.csv`
and update the `python SDK` result column.

Example dry run:

    $ python tools/run_auth_csv_tests.py --dry-run

Run against brokers and write results back to the input CSV:

    $ python tools/run_auth_csv_tests.py --in-place \
        --bootstrap broker-auth.example.com:9093 \
        --anonymous-bootstrap broker-anon.example.com:9092

By default the script writes:
- `auth_tests.python_automated.csv` for CSV output
- `.ignore/auth_tests_python_details.json` for execution details

## check_auth_csv_results.py

Validate the CSV generated by `run_auth_csv_tests.py` against its expected
auth matrix column. The command exits with status `1` when any scenario result
does not match the expected produce/consume outcome, so CI can call it directly.

Example:

    $ python tools/check_auth_csv_results.py auth_tests_verification.python_automated.csv
